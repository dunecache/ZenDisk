# ZenDisk — Tauri v2 migration plan

Status: approved — Windows 10/11 minimum; Windows 7 is unsupported
Branch: `feat/tauri-v2-migration`
Date: 2026-11-20

## Goal

Replace the Neutralinojs shell with Tauri v2:

- signed OTA updates for the installed app
- one NSIS `setup.exe` artifact (no portable exe, no MSI)
- smaller footprint than Electron, native Windows installer
- Windows 10/11 support (Windows 7 is **not** achievable — see blocker)

Non-goals: portable exe, MSI, macOS/Linux bundles, code-signing certificate,
Settings updater UI (Phase 6.6), implementing real disk/file native operations (Phase 6).

## Verification results

Checked against current Tauri docs/schema, plugin READMEs, Rust docs, and the repo.

| # | Finding | Consequence |
|---|---|---|
| 1 | Rust `*-pc-windows-msvc` targets require **Windows 10 or higher** (rustc platform-support docs). Tauri v2's updater needs Rust >= 1.90. | **Tauri v2 cannot ship a supported Windows 7 build.** Tauri's "Supporting Windows 7" page is stale relative to the current Rust toolchain. Win7 must be dropped or a different runtime chosen. |
| 2 | Microsoft's WebView2 distribution docs now describe only Windows 10/11 evergreen. | Second, independent Win7 blocker. |
| 3 | `@tauri-apps/cli@2.12.6` has no Android/Termux binary. | CLI cannot run locally. Builds happen in CI. Icons are generated locally with ImageMagick (present) and committed. |
| 4 | WebKitGTK dev libs absent locally. | No local `cargo check`/`tauri build`. Local gate is `pnpm typecheck`; CI is authoritative. |
| 5 | Config schema confirms `frontendDist`, `devUrl`, `devCsp`, `createUpdaterArtifacts`, `webviewInstallMode` (`embedBootstrapper` + `silent`), `bundle.targets`, `installMode`. | Config keys in this plan are valid. |
| 6 | `--config <json>` merges with `json_patch::merge` (deep merge). | CI can override only `version` and `bundle.createUpdaterArtifacts` without losing `targets`/`icon`. |
| 7 | `createUpdaterArtifacts: true` requires `TAURI_SIGNING_PRIVATE_KEY`. | PR builds must override it to `false`; main builds sign. |
| 8 | Updater skips updates unless the manifest version is newer. | CI must inject a per-build version (`0.1.<run_number>`); `0.0.0` forever would never update. |
| 9 | Updater static JSON needs `version`, `platforms.windows-x86_64.url`, `platforms.windows-x86_64.signature`. | Generate `latest.json` after the NSIS bundle, upload it last. |
| 10 | NSIS output is `src-tauri/target/release/bundle/nsis/<Name>_<version>_x64-setup.exe` + `.sig`. | CI globs for `*-setup.exe` and `*.exe.sig`. |
| 11 | `tauri signer generate` supports `--ci`, `-w`, `-p`; `--ci` with no password produces an empty-password key. | One-off ubuntu workflow can generate the key non-interactively. |
| 12 | Store plugin registers with `Builder::default().build()`; updater with `Builder::new().build()`. | Rust `lib.rs` must use the builder forms, not `init()`. |
| 13 | `Asset` protocol + Tauri custom protocol break `BrowserRouter` on reload. | Switch to `HashRouter`. |
| 14 | Existing icon is 256x256 PNG; ImageMagick, Pillow, ffmpeg are available locally. | Generate `icon.ico` + PNG set now, commit them; no CI icon step. |
| 15 | Renderer has **zero** real Neutralino calls — `client.ts` is all `notImplemented`. | Migration risk is plumbing only; screens do not change. |
| 16 | Existing release `windows-latest` contains only `zendisk-release.zip`. | Delete stale asset after the first Tauri publish. |
| 17 | `actions/checkout@v7`, `setup-node@v7`, `pnpm/action-setup@v6`, `upload-artifact` are current. | Use current majors to clear the Node 20->24 runner annotation. |

## Hard blocker: Windows 7

Two independent reasons, either one is fatal:

1. Rust's MSVC targets: "Windows 10 or higher is required for client installs."
2. Current WebView2 evergreen distribution documents Windows 10/11 only.

Tauri's Windows 7 doc predates the Rust 1.78 minimum-OS change and/or applies to
pinned legacy toolchains. Pinning Rust 1.77 + Tauri 2.0 would break the updater
(needs Rust 1.90), lose security fixes, and is not a supported configuration.

**Recommendation:** proceed with Tauri v2 targeting Windows 10/11. If Windows 7
is non-negotiable, stop here: the realistic options are an EOL Electron 22 build
or staying on Neutralino, neither of which gives modern OTA.

## Decisions

1. Tauri v2, NSIS only, single `setup.exe`; no portable exe.
2. Updater included, as its own commit.
3. Signing key generated by a temporary ubuntu workflow; private key stored as
   `TAURI_SIGNING_PRIVATE_KEY`; public key committed.
4. Minimal plugin set: `fs`, `shell`, `dialog`, `os`, `store`; add `updater`,
   `process` in the updater commit.
5. Version scheme for automated builds: `0.1.<github.run_number>` on main,
   `0.0.<run_number>` on PRs (never published).
6. `webviewInstallMode: embedBootstrapper` (+1.8 MB) — fewer install failures
   than `downloadBootstrapper`, still compatible with older Windows 10.
7. No Authenticode certificate for now; SmartScreen may warn. Documented.

## Step 3 — Plugins

- Register in Rust: `fs::init()`, `shell::init()`, `dialog::init()`, `os::init()`,
  `store::Builder::default().build()`.
- No plugin imports in components/features; only the facade may use them later.

## Step 5 — Updater + signing key

### 5a. Key generation (one-off)

Add `.github/workflows/keygen.yml` (temporary):

```yaml
name: Generate updater signing key
on: workflow_dispatch
permissions:
  contents: read
jobs:
  keygen:
    runs-on: ubuntu-latest
    steps:
      - run: npx --yes @tauri-apps/cli@2.12.6 signer generate --ci -w "$RUNNER_TEMP/zendisk.key"
      - uses: actions/upload-artifact@v4
        with:
          name: updater-keypair
          path: |
            ${{ runner.temp }}/zendisk.key
            ${{ runner.temp }}/zendisk.key.pub
          retention-days: 1
```

Push the branch, then:

```bash
gh workflow run keygen.yml --ref feat/tauri-v2-migration
gh run watch
gh run download <run-id> -n updater-keypair -D "$TMPDIR/zendisk-keys"
gh secret set TAURI_SIGNING_PRIVATE_KEY < "$TMPDIR/zendisk-keys/zendisk.key"
cat "$TMPDIR/zendisk-keys/zendisk.key.pub"   # paste into tauri.conf.json
gh run delete <run-id>                       # removes artifact + logs
rm -rf "$TMPDIR/zendisk-keys"
```

The keypair is generated with an empty password (`--ci`); only the private key
goes to the secret, the public key is committed. Note the trade-off in ROADMAP.

> **Update (2026-11-20):** the key was rotated to a password-protected key
> before any real installs. `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` is set, the new
> public key is in `tauri.conf.json`, and a signed build verified the chain. The
> bridge-release procedure lives in `docs/updater-key-rotation.md`.

## Step 6 — CI rewrite

Rewrite `.github/workflows/build-windows.yml`:

- `actions/checkout@v7`, `pnpm/action-setup@v6`, `actions/setup-node@v7`
  (Node 22, pnpm cache)
- `dtolnay/rust-toolchain@stable`
- `Swatinem/rust-cache@v2` with
  `workspaces: apps/desktop/src-tauri -> target`
- `pnpm install --frozen-lockfile`
- Build step, working dir `apps/desktop`, shell `pwsh`:
  - `$isPr = '${{ github.event_name }}' -eq 'pull_request'`
  - version `0.0.<run_number>` on PR, `0.1.<run_number>` on main
  - write `tauri.ci.json` with `version` and
    `bundle.createUpdaterArtifacts = -not $isPr`
  - `pnpm exec tauri build --config tauri.ci.json`
  - env `TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}`
    (empty on fork PRs; artifacts disabled there)
- Verify:
  - `src-tauri/target/release/bundle/nsis/*-setup.exe` exists
  - on main: matching `*-setup.exe.sig` exists
- On main/dispatch only:
  - generate `latest.json`:
    `version`, `notes`, `pub_date` (RFC 3339), `platforms.windows-x86_64`
    with `signature` (contents of `.sig`) and `url`
    (`https://github.com/<repo>/releases/download/windows-latest/<setup name>`)
  - create the `windows-latest` prerelease if missing
  - upload **in order**: setup.exe -> setup.exe.sig -> latest.json
    (`--clobber`; latest.json last so clients never see a manifest for a
    missing asset)
  - delete the stale `zendisk-release.zip` asset if present
- Keep `contents: write` job permission and the quota workaround.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Win7 requirement resurfaces | Documented blocker: Rust 1.90 + WebView2 require Win10+. Revisit runtime choice, not Tauri config. |
| Tauri CLI absent locally | Icons generated locally and committed; all CLI/build verification in CI. |
| CLI cannot be exercised before CI | Keep Step 1 config minimal; first PR run is the compile gate. |
| `createUpdaterArtifacts` breaks PR builds | Per-event `--config` override to `false`; secret only needed on main. |
| Signing key loss | Secret stored in GitHub; note that losing it prevents future updates. Keygen artifact deleted after import. |
| `latest.json` race | Upload exe, then sig, then manifest last; `--clobber`. |
| Stale CDN manifest | GitHub asset caching (~minutes); acceptable for beta. Use a distinct tag per channel if it becomes a problem. |
| SmartScreen warnings | No Authenticode cert; documented. Add signing in a later phase. |
| Deep-link reload 404 | `HashRouter`. |
| Rust compile errors from plugin APIs | Use verified registration forms (store/updater builders); CI catches the rest. |
| Icon generation differs per machine | Commit the generated icons; no CI dependency on ImageMagick. |

## Rollback

Revert the migration merge commit on `main`. The previous release zip and
Neutralino config remain in git history; CI workflow reverts with the commit.
The updater key can stay in secrets; it is harmless if unused.

## Resolved decision

Windows 7 is not achievable with this stack (Rust MSVC targets and current
WebView2 both require Windows 10+). Proceeding with Windows 10/11 as the
minimum supported platform. The signed updater and single NSIS installer are
the reasons for the switch.
